# Final Project Protocol — Vehicle Heading Axis and Direction Estimation

## 1. Actual problem statement

Given an annotated vehicle crop, estimate both:

1. **Heading axis** — the undirected longitudinal vehicle axis, represented in `[0, 180)` degrees.
2. **Heading direction** — which of the two ends along that axis points in the vehicle's directed heading, producing a final heading angle in `[0, 360)` degrees.

An axis alone cannot distinguish the front-facing end from the rear-facing end. The direction stage must therefore use image evidence from the two ends of the crop and be evaluated against the dataset's directed `heading_deg` annotation.

**Ground-truth axis convention:** `gt_axis_deg = heading_deg % 180`. Do not fold angles into `[0,90]`: 45° and 135° are different undirected line orientations. Existing crop metadata generated by the earlier `[0,90]` folding implementation must be regenerated before the final experiment.

## 2. Method: conventional image processing only; no machine learning

### Stage A — estimate the undirected axis

Keep all five estimators for comparison:

1. PCA on Canny edge points (`pca_edges`)
2. Hough-line aggregation (`hough_edges`)
3. Otsu foreground mask + image moments (`otsu_moments`)
4. PCA/Hough hybrid (`pca_hough_hybrid`)
5. Elliptical-ROI PCA (`pca_roi`)

Each method predicts an axis angle `pred_axis_deg` in `[0, 180)`. The hybrid also records its route.

### Stage B — rule-based directed-end estimate

For each method's estimated axis:

1. Rotate the crop so the positive axis vector points to the right.
2. Apply Otsu thresholding and connected-component selection to estimate the vehicle silhouette.
3. Measure foreground width near the two terminal regions and normalize by the central body width.
4. Apply a fixed geometric rule: the end with the smaller terminal silhouette/taper ratio is presumed to be the front.
5. If the normalized taper difference is below the ambiguity threshold, mark direction unresolved rather than forcing a guess.
6. Combine the selected sign with the estimated axis:
   - sign 1: `pred_heading_deg = pred_axis_deg`
   - sign 0: `pred_heading_deg = (pred_axis_deg + 180) % 360`

This stage is deterministic conventional image processing. It does not fit parameters, learn from labels, or train a classifier. The narrower-end-is-front assumption is a heuristic and may fail for symmetric, occluded, low-resolution, or poorly segmented vehicles. Unresolved cases are excluded from heading-error metrics but remain in the coverage denominator.

**Important:** `heading_deg` must use the same image-coordinate convention as the estimators: x increases right, y increases down, and angles are measured by `atan2(y, x)`. Verify this convention by overlaying ground-truth headings on sample crops before interpreting front/rear labels. If the dataset uses another convention, correct the annotation-to-image conversion before evaluating.

## 3. Ground truth and metrics

### Axis metrics (180-degree periodicity)

- Valid prediction coverage
- MAE
- Median error
- P90 error
- Percentage within 5°, 10°, and 15°
- Breakdowns by vehicle category and axis style

Axis error is the shortest difference modulo 180°.

### Directed heading metrics (360-degree periodicity)

- Direction-resolved coverage
- Directed heading MAE
- Median directed error
- P90 directed error
- Percentage within 5°, 10°, and 15°
- Breakdowns by vehicle category and ground-truth axis style

Heading error is the shortest circular difference modulo 360°. Do not use the 180-degree axis error for directed-heading evaluation.

### Other comparisons retained

- All five axis estimators, including weaker methods
- Hybrid route counts and route-conditioned results
- Axis-aligned versus diagonal crops
- Vehicle-category-wise axis and heading results
- 42-configuration preprocessing ablation
- Crop-size analysis


Vehicle-category classification is not heading-direction classification. Report them separately.

## 4. Leakage control

Use `src.make_experiment_splits` to split by `source_image`. Crops from the same original image must not appear in both train and test.

- Generate axis predictions on both `train_metadata.csv` and `test_metadata.csv`.
- Do not use heading labels to select the direction sign; labels are used only for evaluation.
- Evaluate once on the held-out test crops.
- Fit/select ablation configurations using training data only.
- Do not select the hybrid threshold or direction features using test performance.
- The same fixed geometric rule is applied to each axis method.

Run from the `Codes` directory. The example assumes the dataset is at `data/DRASHTI-HaOBB`.

A small run is valid for debugging and preliminary reporting. For example:

The final run uses `--limit-images 0` and a separate directory such as `crops/full_val`. Always regenerate metadata after the corrected `heading_deg % 180` ground-truth axis calculation. Never mix pilot and full-run output folders.

## 7. Interpretation and reporting rules

- Report axis and directed heading as separate tasks and separate metrics.
- Hough led the earlier 100-crop sample, but that is preliminary only. Do not assume it wins on the full split.
- Retain hybrid, moments and ROI even if they underperform.
- The narrower-terminal-silhouette assumption is a heuristic, not proof of front/rear identity. Inspect representative overlays and report unresolved coverage.
- Check overlays for angle convention, crop rotation and arrow direction.
- Include failed/invalid estimates in coverage denominators.
- Report the number of source images and vehicle crops in each split.
- Never claim full-dataset performance until the full experiment has actually completed.
